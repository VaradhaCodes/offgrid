# Engine spec for the Kotlin port (v2, 5 Sep 2026: route 2 folded in — joint model, heading without the bias state, corrected label lag; changes from v1 listed in §10)

Source of truth: the Python engine in `engine/` (`align.py`, `heading.py`, `filter.py`, `corridor.py`, `mapmatch.py`, `replay.py`). The Kotlin engine must reproduce `engine/replay.py` on a recorded session to the tolerance in §9. Everything below is plain arithmetic on fixed-size arrays; no library calls beyond `sqrt`, `atan2`, `sin`, `cos`, `exp`.

## 1. Frames, units, timing

- Phone frame: Android sensor axes (x right, y top, z out of the screen). Accelerometer at rest reads +g upward. Units m/s², rad/s.
- Bike frame: x forward, y left, z up (right-handed). `v_b = R_pb · v_p`.
- World frame: ENU metres about the session's start anchor: `x = (lon − lon0)·111320·cos(lat0)`, `y = (lat − lat0)·111320`. ENU yaw ψ is measured counter-clockwise from east; a GNSS bearing β (clockwise from north, degrees) converts as `ψ = π/2 − β·π/180`.
- Clocks: IMU `SensorEvent.timestamp` and `Location.getElapsedRealtimeNanos()` are the same monotonic clock. All engine times are seconds since the session start.
- Rates: IMU consumed at 100 Hz (§2), engine tick 10 Hz, GNSS ~1 Hz, map matcher 2 Hz (display only).

## 2. IMU resampling (native 420 Hz → 100 Hz)

The Python reference resamples with a zero-phase 4th-order Butterworth at 40 Hz then linear interpolation to a 10 ms grid. The app must not alias the 60–210 Hz vibration into the model's 10–40 Hz bands, so it runs a **causal** 4th-order Butterworth (two biquads) at 40 Hz on the native stream and samples the filtered value at each 10 ms grid time by linear interpolation between the last two native samples. Biquad coefficients (fs = 420 Hz, fc = 40 Hz, second-order sections, direct form II transposed) are generated by `scipy.signal.butter(4, 40, fs=420, output='sos')` and listed in `engine/export/resample_constants.json` (written by `engine/export/export.py`). The causal filter lags the zero-phase reference by ~7 ms; the conformance tolerance (§9) absorbs it.

## 3. Alignment (`align.py`)

State: `g_ref[3]` (gravity in the phone frame), `R1[3×3]`, `psi` (forward-axis yaw in the levelled frame), `R_pb = Rz(−psi)·R1`.

3.1 Levelling. `u = g_ref/|g_ref|`, `z = (0,0,1)`, `k = u × z`, `s = |k|`, `c = u·z`. If `s < 1e-9`: `R1 = I` (c > 0) or `diag(1,−1,−1)`. Else `K = skew(k/s)`, `θ = atan2(s, c)`, `R1 = I + sin θ·K + (1 − cos θ)·K²`.
- Initial `g_ref` = mean accelerometer over the start stand, trimmed 1 s at both ends (≥ 3 s of data).
- Ride-time `g_ref`: while riding, keep a 0.5 s trailing mean of the accelerometer `a_lp` and gyro `w_lp` (bias removed). A sample is *gated* when `|w_lp| < 0.15 rad/s`, `| |a_lp| − |g_ref| | < 1.0 m/s²`, speed > 1.5 m/s and |GNSS acceleration| < 0.3 m/s² (GNSS acceleration = difference of consecutive GNSS speeds over their interval, 3-fix trailing mean; when GNSS is absent use the filter's speed). Accumulate gated `a_lp` in 10 s blocks; the first complete block replaces the stand estimate; later blocks update `g_ref ← 0.8·g_ref + 0.2·block_mean`. Moved-phone rule: if two consecutive blocks differ from `g_ref` by > 3°, set `g_ref = block_mean` (re-level; `psi` is kept).
- Constants: LP 0.5 s, block 10 s, gates 0.15 rad/s, 1.0 m/s², 1.5 m/s, 0.3 m/s², move 3°.

3.2 Forward axis. Levelled gyro `w_l = R1·(w − b)`; band-pass `w_bp = mean_{0.25 s}(w_l[0:2]) − mean_{2 s}(w_l[0:2])` (trailing means). Over moving samples (speed > 1.5 m/s) accumulate the 2×2 second-moment matrix `M += w_bp·w_bpᵀ`. `ang = 0.5·atan2(2·M01, M00 − M11)`, `e = (cos ang, sin ang)`. Sign: `f = R1·a − |g_ref|·z` over the first speed-up window (from 2 s before the first GNSS speed > 1 m/s to 6 s after, only samples with GNSS acceleration > 0.15 m/s²), `m = mean of the horizontal f`, `psi_init = atan2(m_y, m_x)`; if `cos(ang − psi_init) < 0` then `ang += π`. `psi = ang`. Use `psi_init` until 20 s of moving samples exist, then `psi` (recomputed every 10 s from the running M).

3.3 Validation numbers (route 1, 20 runs): psi spread 2.1° RMS; gyro-z vs GNSS course-rate slope 0.93–1.09.

## 4. Heading filter (`heading.py`, `HeadingFilter`)

Runs at 100 Hz on bike-frame samples `a_b = R_pb·a_p`, `w_b = R_pb·(w_p − bias_p)` where `bias_p` is the robust stand estimate (§4.4).

4.1 Attitude. Quaternion `q` (bike → world), start `(1,0,0,0)`. Per sample with dt: `q ← q ⊗ exp((w_b − b)·dt)` where `b = (0, 0, b_z)` is the filtered z-bias (x/y biases are already removed in `bias_p`); `exp(v)` = `(cos(|v|/2), v/|v|·sin(|v|/2))`; normalise. Tilt correction, only if `|w_lp| < 0.15` and `| |a_lp| − g | < 1.0` (0.5 s trailing means as in §3): `u_meas = a_lp/|a_lp|`, `u_pred = Rᵀ(q)·z = (2(xz − wy), 2(yz + wx), 1 − 2(x² + y²))`, `e = u_meas × u_pred`, `q ← q ⊗ exp(e·dt/10)`. Heading `ψ = atan2(2(wz + xy), 1 − 2(y² + z²))`.
Raw integral for latency: `I += w_b_z_raw·dt` (raw = before bias removal) with a 4 s ring buffer of (t, I).

4.2 Covariance. State error `[δψ, δb_z]`, `P` 2×2, initial `diag((30°)², P_b0)`. **Default (stand quiet)**: the bias is *not* refined — `b_z` stays at the robust stand value for the whole session, `P_b0 = (0.2°/s)²` is carried only for the P bookkeeping (K1 is forced to 0 in §4.3). Measured over 30 runs of both routes at the 30 s cut: 28/30 under 3°, worst 4.1°; the v1 bias state was 25/30, worst 11.4° (a 0.05–0.1 °/s bias-state error is harmless over 60 s and 10–20° over 200 s). **Stand not quiet** (quiet-chunk fraction < 0.5 or net rotation > 5° during the start stand, both computable online): use the plain start-stand mean as `b_z0`, `P_b0 = (2°/s)²`, refine the bias (K1 active) with clamp ±3 °/s; the heading is trustworthy only 60 s after motion start (a 1.9 °/s contaminated bias converges to < 5° by then), so the app must not arm an outage earlier on such a run. Per sample: `P00 ← P00 − 2·dt·P01 + dt²·P11 + (0.1°)²·dt`, `P01 ← P01 − dt·P11`, `P11 ← P11 + (0.002°/s)²·dt`.

4.3 GNSS course measurement, at each fix with speed v > 1.5 m/s, course finite, and no turning for 1.5 s (turning = `|w_lp_z − b_z| > 0.10 rad/s`): course `c = atan2(Δy, Δx)` from the last two fix positions (interval 0.5–1.6 s, ground speed > 1.5 m/s). First accepted course initialises: `ψ ← c` (rotate q about world z by `wrap(c − ψ)`), `P = diag((10°)², P11)`. Afterwards: `I_τ = I(t) − I(t − 0.5 s)`, `h = ψ − I_τ + 0.5·b_z`, `ν = wrap(c − h)`, `H = [1, 0.5]`, `r = (0.3/v)² + (0.2·w_lp_z)² + (2°)²`, `S = H P Hᵀ + r`. Gate: if `|ν| > 5√S` count a rejection; after 5 consecutive rejections rotate ψ by ν, set `P00 = (10°)²`, `P01 = 0`, and continue. Else `K = P Hᵀ/S`; set `K1 = 0` unless the stand-not-quiet mode of §4.2 is active (then also `K1 = 0` when v < 2 m/s); rotate q about world z by `K0·ν`; `b_z ← clamp(b_z + K1·ν, b_z0 ± clamp)` with clamp 3 °/s in that mode; Joseph update `P ← (I − K H) P (I − K H)ᵀ + K Kᵀ r`, symmetrise.

4.4 Robust stand bias (`session.robust_gyro_bias`): 1 s chunks over the stand (trimmed 1 s each side); keep the quietest half by summed variance, drop chunks with max |mean| > 0.01 rad/s; bias = mean of the rest (median of all chunks if fewer than 3 remain). Route-1 result: 19/20 runs < 3° mean heading error at the 30 s cut.

## 5. Fusion filter (`filter.py`, `Filter`), 10 Hz tick

Common constants: `SIG_A = 1.0 m/s²` (speed random walk), `SIG_M_FLOOR = 0.15 m/s`, `SIG_VG = 0.3 m/s`, `SIG_ZUPT = 0.05 m/s`, `LAG_POS = 0.5 s`, `LAG_V = 0.2 s` (measured Doppler-speed latency, both routes), `REC_INFL = 4`, `REC_S = 3 s`, gate 5σ, `N_REJECT = 5`; scale state `SIG_K0 = 0.05`, `T_K = 600 s`, `K_VMIN = 2 m/s`, `K_AMAX = 0.3 m/s²`, `k ∈ [0.5, 1.5]`. **k off on bicycle roads in both modes** (measured on 30 runs of two roads: it costs 0.3–3 % drift at the 30 s cut in the general mode and flips corridor runs both ways); on only for an external IMU with a grossly biased speed source (IO-VNBD, −23 %: 24 → 14 %).
Generic update (all measurements): `S = H P Hᵀ + R`; if `|ν| > 5√S` reject (return false) else `K = P Hᵀ/S`, `x += K ν`, Joseph form, symmetrise.
Every tick keep a 4 s ring buffer of (t, px or s, py, v) for latency.

5.1 General mode. `x = [px, py, v, k]`, `P0 = diag(9, 9, 1, SIG_K0²)`. Predict with dt and heading ψ: `px += v cos ψ dt`, `py += v sin ψ dt`, `F = I + [F02 = cos ψ dt, F12 = sin ψ dt]`, `P = F P Fᵀ + diag(0, 0, (SIG_A dt)², 0)`; if k is enabled and GNSS was healthy at the last fix: `P33 += 2 SIG_K0²/T_K·dt`.
Model speed each tick (`v_m, σ_m`, stop flag): if stop flag → `z = 0`, `H = [0,0,1,0]`, `R = SIG_ZUPT²`, then `v = max(v, 0)`. Else `h = v/k`, `H = [0, 0, 1/k, −v/k²]` (H3 = 0 if k disabled or its gate is closed), `R = max(σ_m, SIG_M_FLOOR)²`, then `v = max(v, 0)`, `k = clamp(k, 0.5, 1.5)`. When k's gate is closed, zero the k row/column of P except P33 before the update.
GNSS fix (t_f, x, y, v_g, acc) when not withheld: inflation `infl = REC_INFL` while `t − t_return < REC_S` (t_return = the tick of the first fix after an outage), else 1. `Rp = (max(acc, 3)·infl)²`, `Rv = (SIG_VG·infl)²`. Position: take the delayed state `(px', py')` at `t_f − LAG_POS` from the ring buffer; update px with `ν = x − px'`, `H = [1,0,0,0]`, `R = Rp`; same for py. If both were rejected, count; after 5 consecutive, shift the current position by `(x − px', y − py')`, set `P00 = P11 = Rp`, `P01 = 0`. Speed: delayed `v'` at `t_f − LAG_V`; if `v_g > 0.3`: `ν = v_g − v'`, `H = [0,0,1,0]`, `R = Rv`. k gate: open when the last three fixes exist, `|v_g(last) − v_g(first)|/Δt < K_AMAX`, `v_g > K_VMIN`, `infl = 1`.
Outage (withheld or the rule-1 detector fired): no GNSS update; mark `gnss_ok = false`, close the k gate.

5.2 Corridor mode. Polyline vertices in ENU, cumulative arc length `S_i`, unit tangents `T_i`. `x = [s, v, k]`, `P0 = diag(9, 1, SIG_K0²)`, travel direction `dir ∈ {−1, 0, +1}`, held lateral offset `d`. Predict: `s += dir·v·dt`, `F = I + [F01 = dir·dt]`, `P = F P Fᵀ + diag(0, (SIG_A dt)², 0)`. Model/ZUPT as in 5.1 with indices `[1]` for v and `[2]` for k. GNSS fix: project `(x, y)` onto the polyline → `(s_g, d_g)` (nearest point over all segments, `d_g` signed positive to the left of travel); keep the last 8 `(t_f, s_g)`: with ≥ 4 and `v_g > 1`, if `|s_g(last) − s_g(first)| > 3 m` set `dir = sign`. `d ← d + (d_g − d)·(1 if infl = 1 else 0.3)`. Update s with the delayed `s'` at `t_f − LAG_POS`: `ν = s_g − s'`, `H = [1,0,0]`, `R = Rp`; speed as in 5.1. Output position `p = point(s) + d·n(s)`, `n = (−T_y, T_x)`; heading output = tangent direction · dir.
Off-corridor fallback (app): if a healthy fix projects with `|d_g| > 15 m` for 3 consecutive fixes, switch to the general mode initialised at the fix.

5.3 Physical stop rule (hard override, computed from the last 0.5 s of bike-frame samples): vibration RMS `sqrt(mean(|a − mean(a)|²)) < 0.6 m/s²` AND gyro RMS `sqrt(mean(|w|²)) < 0.06 rad/s` → stop flag. The displayed speed is forced to 0 while the flag holds.

5.4 Real-outage detector (rule 1): fix gap > 1.5 s, or accuracy > 30 m, or satellites used < 4 on two consecutive epochs, or mean C/N0 of used signals < 22 dB-Hz, or the simulated flag → withheld. Mode names for the UI: GNSS_INS, INERTIAL (withheld), RECOVERING (first 3 s after return).

## 6. Corridor polyline (`corridor.py`)

`data/map/corridor_route1.geojson` (37 vertices, 339 m incl. 15 m overhangs; A at s = 15.0, B at s = 334.9) and `data/map/corridor_route2.geojson` (41 vertices, 927 m: Cricket Ground road → library junction → 2011 Street → 120° left at s = 464 m → Circular Road north, plus a 20 m straight overhang past B; A at s ≈ 13, B at s ≈ 905; every kept run projects monotonically with 2.0 m median lateral offset, max 9.1 m). The demo road is route 2 (docs/11, step 11). Projection: for each segment `u = clamp(((p − A)·T)/L, 0, 1)`, closest point `A + u L T`, distance; take the minimum; `s = S_i + u L_i`; `d = T_x(y − c_y) − T_y(x − c_x)`.

## 7. Map matcher (`mapmatch.py`) — display only

Not part of the estimate (measured: its feedback degrades the general mode). If shown: candidates within 25 m, emission `−0.5(d/5)²` plus `ln 0.05` if the heading differs from the undirected edge bearing by > 60°, transition `−|route − travelled|/5`, output the state 3 s back on the best path, confident when the log-probability margin > ln 20.

## 8. Speed model (`engine/speed_model/`, deployment file `data/speed_model/models/cnn_r100_w256_joint_deploy.tflite`; the v1 file `cnn_r100_w256_deploy.tflite` was route-1-only on mis-lagged labels and is superseded)

Input: one window of the last **256** bike-frame samples at 100 Hz (2.56 s), channels `[ax, ay, az, gx, gy, gz]` in m/s² and rad/s with gravity and gyro bias left in (`R_pb` applied, nothing else), shape `[1, 256, 6]` float32, per-channel z-score `x' = (x − mean_c)/std_c` with
mean = [0.03391, 0.00139, 9.30145, 0.00019, -0.0067, -0.00014], std = [1.04142, 1.31722, 1.56807, 0.14452, 0.06602, 0.19358] (all 30 training runs; stored in `cnn_r100_w256_joint_deploy_export.json`).
Output `[μ, log σ²]`: speed `v_m = max(μ, 0)` m/s, `σ_m = exp(0.5·clamp(log σ², −6, 4))`. `μ` is the speed **at the window's end** (training label = receiver Doppler speed reported 0.2 s later, the measured receiver latency; the v1 labels were shifted the other way and the v1 model output the speed 0.8 s in the past). Evaluated every 0.1 s on the newest window (window end = tick time; windows never straddle the stand/ride boundary in training, at runtime they are just the last 2.56 s).

Architecture (PyTorch `train.build_model('cnn')`, width 32, 57602 parameters): four `Conv1d` blocks (6→32 k7 s2, 32→64 k5 s2, 64→64 k5 s2, 64→96 k3 s2; symmetric zero padding k//2; BatchNorm; ReLU), global average pool over time, Dense 96→64 ReLU, Dense 64→2. The Keras twin uses explicit `ZeroPadding1D(k//2)` + `Conv1D(padding='valid')` so the alignment matches PyTorch exactly.

Training set: all 20 route-1 and 10 route-2 kept runs (early stopping on 2 inner runs); held-out numbers in docs/11 step 11 (speed MAE 0.179 m/s on route 1, 0.164 on route 2). Exports (verified on 2000 real windows, `engine/export/export.py`): ONNX opset 17 `cnn_r100_w256_joint_deploy.onnx` (230450 bytes, ops ['Conv', 'Gemm', 'ReduceMean', 'Relu', 'Transpose'], max |Δ| vs PyTorch 1.9e-06); TFLite float32 `cnn_r100_w256_joint_deploy.tflite` (239688 bytes, ops CONV_2D ×4, FULLY_CONNECTED ×2, MEAN, PAD ×4, RESHAPE/EXPAND_DIMS, max |Δ| 1.9e-06). Latency on this Mac, single thread: ONNX Runtime 0.067 ms, LiteRT 0.066 ms per window; the phone figure must be measured inside the APK (LiteRT, `setUseXNNPACK(true)`, `setNumThreads(1)`, runtime version pinned; R2). Budget 5 ms.

**Per-corridor model override.** The app loads the model by corridor id from its config: the route-2 corridor uses `cnn_r100_w256_r2deploy_s1.tflite` (route-2-only training, all 10 runs, seed 1; 239688 bytes, max |Δ| vs PyTorch 2.4e-06; ONNX 230450 bytes, 1.4e-06; same architecture and input contract; normalisation mean [0.02002, 0.00715, 9.80656, -0.00035, -0.00381, 8e-05], std [1.08918, 1.33808, 1.41249, 0.14498, 0.0655, 0.18375] from `cnn_r100_w256_r2deploy_s1_export.json`), every other corridor and the general mode use the joint model above. Measured reason (docs/11 step 11, like-for-like leave-one-run-out on route 2): corridor drift 1.52 % / 5.73 % with the route-2 model against 2.50 % / 7.95 % with the joint set, a gap inside the seed spread but consistent in the along-track bias. **Acceptance check for any shipped instance**: its median speed bias on its own training runs must be within ±0.02 m/s on every road it serves (seed 0 of this model failed at −0.073 m/s and was discarded; seed 1 reads −0.012; the joint instance +0.007 on route 2, +0.025 on route 1).

Physical stop rule (§5.3) overrides the model output; the filter consumes `v_m`, `σ_m` and the stop flag (§5).

## 9. Conformance test

Two reference sessions, both with the outage from motion start + 30 s to the end, corridor mode, k off, heading per §4 default, model = the frozen joint deployment model (§8): route 2 `data/route2/sessions/20260905_033817_SNU_AJB_AB_run4` → `data/qa/replay/r2only/20260905_033817_SNU_AJB_AB_run4_corridor_mm0.csv` with the route-2 corridor model `cnn_r100_w256_r2deploy_s1`, the demo configuration (CONFORMANCE_R2, 2.81 %, endpoint 22.1 m; the joint-model variant of the same run is `data/qa/replay/20260905_033817_SNU_AJB_AB_run4_corridor_mm0.csv`, 2.62 %), and route 1 `data/route1/sessions/20260905_003612_SNU_AJB_AB_run1` → `data/qa/replay/20260905_003612_SNU_AJB_AB_run1_corridor_mm0.csv` (CONFORMANCE_R1). Columns at 10 Hz: t_s, x_m, y_m, lat, lon, v, heading_deg, mode, k, sigma_pos. Reference results (v2 engine): route-2 run 4 with the corridor model, outage 789 m / 218 s, endpoint 22.1 m (2.81 %), RMSE 15.1 m (joint model on the same run: 20.7 m, 2.62 %); route-1 run 1 outage 229 m / 82 s, endpoint 6.7 m (2.92 %), RMSE 6.0 m, 6.8 m after the stop. Both runs are in the model's training set: they are conformance references, not accuracy claims. The Kotlin engine, fed the same session files, must produce a track with `max |Δposition| < 1.0 m` against that CSV over the whole session and identical mode transitions within ±0.2 s. Heading must agree within 1° and the model's speed within 0.02 m/s (float32 vs float64 and the causal resampler are inside these tolerances).

## 10. Changes from v1 (route 2 folded in, 5 Sep 2026; measurements in docs/11 step 11)

1. **Label lag corrected**: v1 labelled IMU time t with v_GNSS(t − 0.7 s) (wrong sign of a mis-estimated lag), so the v1 model output the speed 0.8 s in the past. v2 labels are v_GNSS(t + 0.2 s), the measured receiver latency on both routes; the model's `μ` is the current speed. `LAG_V` in §5 follows (0.7 → 0.2 s).
2. **Heading without the bias state** by default (§4.2, §4.3): the v1 [ψ, b_z] state cost up to 20° on route 2's 200 s outages; ψ is still refined from the position course, the robust stand bias is held. The bias state is kept only for a stand that failed the quiet check, and then the outage is trusted 60 s after motion start.
3. **Scale state k off on bicycle roads** in both modes (§5).
4. **Joint deployment model** trained on both roads (§8); replaces `cnn_r100_w256_deploy`. The route-2 corridor overrides it with `cnn_r100_w256_r2deploy_s1` (per-corridor model selection by config; shipped instances pass a ±0.02 m/s training-bias check).
5. **Route-2 corridor** (§6) with a 20 m straight overhang past B; route 2 is the demo road.
6. **Stop latency reference**: the hard rule fires 0.7 s (median, 0.2–1.7 s) after rolling vibration ends; the receiver's Doppler zero precedes the physical stop by 0.6 s median, so latency must be scored against the physical stop.
7. Conformance references (§9): route-2 run 4 added; both regenerated with the v2 engine and model.
